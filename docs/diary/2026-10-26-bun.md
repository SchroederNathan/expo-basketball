# Bun migration

The project now uses Bun 1.2.22 for dependency installation, script execution, and tests. The package manager field and every EAS build profile pin that version. The committed text lockfile is bun.lock. Frozen installs use `bun install --frozen-lockfile`.

Bun imported the existing dependency resolutions before the npm lockfile was removed. The TypeScript runner dependency is no longer needed. Bun executes the API check directly and runs the existing tests with its built-in test runner. The tests keep their node:test imports and assertions; the same 38 behaviors passed under Bun before changing any tests.

Use `bun start` for Metro, `bun run ios` or `bun run android` for native development builds, and `bun expo install <package> --bun` for SDK-compatible dependencies. Expo's CLI continues to select its supported JavaScript runtime. Node 22 or newer remains installed for native tooling that downloads Expo templates. [Expo's Bun guide](https://docs.expo.dev/guides/using-bun/) describes that requirement and EAS lockfile detection.

Earlier verification receipts retain the commands that actually ran at the time. Current Bun checks are recorded separately so the migration does not rewrite that evidence.
